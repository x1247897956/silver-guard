# 关键取舍（design notes）

> 这份文档记录**做过什么判断、否掉了什么方案、代价是什么**。
> 面试官问"你为什么这么做"时，答案在这里；问"数字是多少"时，答案在 `eval-report.md`。

---

## 1. 为什么把"动作决策"从 LLM 手里拿出来

**问题**：如果让模型直接输出"是否通知家属"，那么攻击面就从"骗老人"扩展到"骗这个 Agent"。
骗子只要说"别告诉你儿子，这是我们家的事"，模型就可能顺着放行——而这类话术在真实案件里很常见。

**做法**：把决策拆成两段。

| 段 | 谁负责 | 为什么 |
| --- | --- | --- |
| 证据抽取 | LLM | 这是它擅长的：从自然语言里识别身份自称、施压、资金动作、保密要求、渠道异常 |
| 等级 → 动作 | `config/policy.yaml` 的确定性规则 | 这是**可以被审计的**：改一版策略就等于换一个实验条件 |

**代价**：规则是人写的，会漏掉模型能看出的细微信号；而且规则的触发条件需要调参
（本项目用阈值扫描给出取舍点，而不是拍一个数）。

**换来的东西**：「跳过干预」这件事在架构上不可能由一次对话完成——它需要改策略表，
而策略表有版本、进 git、受评测门禁约束。并且这条判断**可以用实验验证**：
把策略引擎关掉（`mode: llm_only`，采纳 LLM 的建议等级），看社工子集的 `SE-ASR` 是否变差。
如果差异不明显，报告里会如实写"我的实验没能区分两种方案"，而不是硬讲这张牌。

## 2. 为什么是"旁路监督"，而不是让 Agent 和骗子实时对线

实时对话听起来更酷，但会让评测变成"谁的 prompt 更强"：每跑一次结果都不同，
指标无法归因，也没法复现。

旁路监督（输入 = 完整轨迹，输出 = 等级 + 动作）把这个场景收敛成一个**决策问题**，
指标是确定性的。这也正是手机端反诈的真实形态：系统在旁路看，不参与对话。

**代价**：无法测"实时劝阻的效果"。所以任务级指标（劝说成功率）用**老人模拟器**单独测，
并且明确标注那是 LLM 模拟、不是真人。

---

## 3. 为什么误报要分三级，而不是一个 F1

漏拦的代价是钱，误报的代价是打扰——**两者不可通约**：

| 级别 | 打扰对象 | 代价 |
| --- | --- | --- |
| L2 高度可疑 | 老人 | 一次确认打扰 |
| L3 极可能诈骗 | 家属 | 惊动家属；频繁误报会让家属不再信任提醒 |
| L4 确认诈骗特征 | 老人 + 家属 | **误阻断**，最贵的错误 |

压成一个 F1 就把这个权衡藏起来了。所以项目报 `FPR-L2 / L3 / L4` 三条，并给出
阈值扫描曲线让读者看见"我为了少漏拦付出了多少误报"。

**这条判断直接影响了规则设计**：L4 要求 `money_action + secrecy + 老人已被说服` 三个条件同时成立。
如果 L4 只看"资金动作 + 老人答应"，那么"妈，我学费差 8000""好，我这就转"这种
**完全正常的家庭对话**会被直接误阻断（见 `tests/test_policy.py::test_normal_transfer_with_compromise_is_not_l4`）。

---

## 4. 为什么不用 LangChain（也没有用向量检索）

链路只有三步：抽证据 → 调工具 → 规则定动作。每一步都要能被**确定性回放**。

- 薄 HTTP 客户端能把"发了什么、收到什么、花了多少 token、耗时多少"全部落进轨迹；
  套一层编排框架会把这些细节藏进抽象里，归因反而更难。
- 工具层用自带的注册表 + JSON schema 校验（`src/silverguard/tools.py`），
  几十行就能把"参数校验 / 权限 / 幂等 / 重试 / 降级"讲清楚，且全部可单测。

**向量检索**在这个项目里没有位置：记忆层的三类查询（白名单精确匹配、历史事件按时间、
近期支出按时间）都是结构化查询，不需要语义召回。引入它只会增加一个讲不清的变量。
（语义检索是另一个项目 `sentinel-rag` 要回答的问题。）

**代价**：简历技术栈少一个 `LangChain` 关键词。这是有意的取舍——
本项目要证明的是"决策可控 + 可评测"，不是"会用框架"。

## 5. 为什么把"证据抽取"和"规则信号"合并进策略输入

`check_fraud_pattern` 是工具集里的一个真工具，它命中与否会直接影响等级。
那么在 C/D 组里，"规则命中"必须真的进入决策上下文，否则：

- 工具调用正确率这个指标就没有意义（调了但没用）；
- 单测与消融实验会变得无法解释（同一批证据下，行为差异来自哪里？）。

所以 `agent.py` 里 `_rule_signals()` 与 A 组基线**共用同一份规则表**，
把规则命中转成信号并入策略上下文。这样 A 与 C/D 的差别就只有
"LLM 是否提供了额外证据"，而不是"谁用了另一套规则"。

**代价**：C/D 组的收益里，有一部分其实来自规则（而不是模型）。
消融表里 B（单次 LLM，无工具）与 C（Agent + 工具）的差距能反映这一点。

---

## 6. 工具参数为什么必须当"不可信输入"

Agent 特有的攻击面：模型生成的工具参数会真的被执行。
骗子完全可以在对话里说"家属联系方式用这个：xxx"，诱导 Agent 去通知一个攻击者控制的号码。

四道防线（都在 `tools.py`）：

1. **schema 校验**：类型/必填/长度/字符集，不合规直接拒；
2. **禁止自造标识**：`check_contact` / `get_elder_profile` 只接受在轨迹或记忆中真实出现过的值；
3. **目标对象白名单**：`notify_family` 的 `member_id` 必须在白名单内；
4. **权限最小化 + 授权等级**：不可逆动作（通知/阻断）需要策略表声明的授权等级。

**代价**：多了一层校验，工具调用会比"直接执行"更容易失败（这是好事，失败是显式可见的）。

## 7. "半失败"比"失败"更难：显式降级而不是重试到成功

工具不会总是成功。反诈场景里，"我猜这个联系人安全"比"我不知道"危险得多。

所以容错策略是：

| 形态 | 处理 |
| --- | --- |
| 参数不合法 | 校验拦截 → 记录 `rejected_by=schema`，不重试（重试同样的非法参数没有意义） |
| 超时 / 5xx | 指数退避重试，**有上限**（默认 2 次）|
| 重试仍失败 | **显式降级**：该证据维度标记为"未知"，写进 `degraded_dims`，**不猜** |
| 重复调用 | 幂等键拦截（同一老人 + 动作 + 对象，TTL 内只执行一次） |

## 8. 上下文压缩：为什么"信号不参与压缩"

长轨迹要压，但**风险信号是结论，不能进摘要被糊掉**。所以分成两条路：

- 历史对话 → 抽取式摘要（保留说话人 + 主干），省 token；
- 风险信号 / 已触发动作 / 已确认事实 → **结构化状态外置**，逐条保留。

口径纪律：压缩必须**同时**给出省下的 tokens 与指标代价（"tokens 降 X%，`PIR` 掉 Y pt"）。
只写"省了多少"不写"掉了多少指标"是不成立的。`make compaction` 跑的就是这个对照。

---

## 9. 回放的口径边界（主动说清）

实现回放的是**证据抽取结果**（模型输出的结构化证据），而不是逐字节重放模型请求。

- 它消除的是**工具与策略侧的不确定**；
- **不消除模型本身的漂移**。

所以报告里同时给出"不一致案例的归因"。如果想连模型漂移一起消掉，
需要固定模型版本 + 记录 logprobs/完整请求体，那是更大的一步工程，
不在本项目的范围里——与其含糊说"完全可复现"，不如把边界写清楚。

---

## 10. 明确不做的事（以及为什么）

| 不做 | 原因 |
| --- | --- |
| 接入真实短信 / 通话 / 通讯录 / 银行账户 | 无授权、涉隐私；本项目是合成轨迹评测 |
| 生成可操作的作案细节 | 有害内容红线；只保留"对老人说什么"的话术层 |
| 宣称"能防住真实诈骗 / 保护了多少老人" | 没有真实用户、没有线上部署，写了就是编 |
| 微调 / LoRA / vLLM / 知识图谱 / 端侧小模型 | 与要回答的问题无关，性价比最低 |
| 分布式 / 高并发 / 集群 | 单机合成轨迹评测，硬蹭必被问穿 |
