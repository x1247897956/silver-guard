# SilverGuard —— 银发反诈守护 Agent：多轮风险决策 + 分级干预 + 对抗式评测

> 本仓库是「**Agent 工程三件套**」之一：`sentinel-rag`（检索正确性）· **`silver-guard`（决策可控性）** · `dsh-llm-guard`（输入输出安全）。
>
> Agent 工程三件套：[`sentinel-rag`](https://github.com/x1247897956/sentinel-rag)（检索）· **silver-guard（决策与对抗）** · [`dsh-llm-guard`](https://github.com/x1247897956/dsh-llm-guard)（护栏）。

**它解决什么问题**：骗子不会只说一句话。他们会用十几轮铺垫建立身份、制造紧迫、要求保密，
最后才提转账。单轮分类器看不出这种结构，而"转账之后才提醒"等于没有保护。
SilverGuard 读**完整的多轮轨迹**，逐轮抽取风险证据、调用确定性工具，输出**风险等级 + 分级干预动作**。

**一个关键设计选择**：不让大语言模型决定"要不要通知家属"。
LLM 只负责它擅长的（从自然语言里抽证据），**最终等级与动作由独立的确定性策略表决定**——
因为"说服模型放行"本身就是一个攻击面。当前小样本 `SE-ASR` 对照未能区分策略引擎开关；报告如实记录了这一限制，设计理由不能当成实验结论。

数字的口径要点：

- **`PIR`（转账前拦截率）是本项目的核心指标**：`#{首次 ≥L2 的轮次 < transfer_turn} / #{transfer_turn ≠ null}`。
  拦在资金动作**之后**只能算事后报警，不算拦住。
- **误报分三级**（L2 只打扰老人 / L3 惊动家属 / L4 误阻断），因为三种代价不可通约，
  压成一个 F1 就把这个权衡藏起来了。
- **`SE-ASR`** 只在当前数据集中已标注的社工子集上算（本轮主要是保密要求）；类别覆盖和条数见审计报告。

## 快速开始

```bash
git clone <this-repo> && cd silver-guard
cp .env.example .env        # 填 DEEPSEEK_API_KEY（.env 已被 .gitignore 忽略）

make setup                  # 装依赖并自检（uv，Python 3.11）
make demo                   # 离线：内置多轮公检法样例，逐轮打印信号→等级→动作
make test                   # ruff + pytest（全部离线，不需要 API key）

make run                    # 启动 FastAPI 服务（127.0.0.1:8000）
make eval                   # 全量评测（四组消融）→ data/eval-dev.{json,md}
```

不需要模型也能跑的部分（CI 里也跑这些）：

```bash
make policy          # 策略表版本 / 档位 / 热加载计数
make hotreload       # 改一版策略 → 不重启观察行为变化；再故意写坏 YAML → 保留旧策略
make guard           # 状态机演示：等级单调不降 + 干预幂等（同一家属只打扰一次）
make dataset-audit   # 数据集合规与结构预筛
```

服务接口：

```bash
curl -s localhost:8000/assess -H 'content-type: application/json' -d '{
  "case_id":"demo","turns":[
    {"role":"fraud","text":"您好，这里是市局经侦支队，请问是李阿姨本人吗？"},
    {"role":"elder","text":"是我，出什么事了？"},
    {"role":"fraud","text":"您名下一张卡牵扯到一起案子，需要配合核查，先不要挂断。"},
    {"role":"fraud","text":"结案前这件事不能告诉任何人，包括子女，否则算泄密。"},
    {"role":"fraud","text":"现在请您把资金转到我们的核查账户，核实无误会原路退回。"}]}'
```

## 关键设计取舍

- **策略表独立于代码**（`config/policy.yaml`）：策略是"机构的处置口径"，不是代码逻辑。
  它必须能改、能回滚、能追溯。所以它独立版本化、**热加载**（改文件不重启即生效）、
  **解析失败保留旧策略并告警**（`make hotreload` 现场演示这两件事）。
  否掉的方案：把等级→动作映射写成 `if/else`。那样"改策略"就等于"改代码 + 重新部署"，
  评测报告里的指标变化也就无法归因到某一版策略。
- **LLM 只抽证据，规则定动作**：如果让模型直接决定是否通知家属，那"别告诉我儿子"这句话
  就可能让模型放行。现在"跳过干预"在架构上不可能由一次对话完成——它需要改策略表，
  而策略表有版本、进 git、受评测门禁约束。
- **工具参数当不可信输入**：工具参数是模型生成的。所以 `check_contact` / `notify_family`
  只接受**在轨迹或记忆里真实出现过**的标识符，模型自造即拒；不可逆动作（通知/阻断）
  需要策略表声明的授权等级。骗子完全可以在对话里喂一个号码让 Agent 去"通知家属"，
  这条防线是为此存在的（见 `tests/test_tools.py::test_contact_rejects_model_invented_identifier`）。
- **旁路监督，而不是让 Agent 和骗子实时对线**：实时对话会让评测变成"谁的 prompt 更强"，
  每次跑结果都不同、没法归因。旁路监督把问题收敛成"给定轨迹判风险 + 定动作"，指标确定。
- **阈值扫描而不是一个 F1**：漏拦的代价是钱，误报的代价是打扰，两者不可通约。
  项目给出 3–5 组阈值下的（漏拦率, 误报率）对，并说明阈值定在哪、为什么。
- **不用 LangChain**：链路只有"抽证据 → 调工具 → 规则定动作"三步，
  而每一步都要能被**确定性回放**。一层薄 HTTP 客户端把"发了什么、收到什么、花了多少
  token、耗时多少"全部落进轨迹，比套一层编排框架更容易做归因。工具层是自带的注册表 +
  schema 校验（见 `src/silverguard/tools.py`）。
- **基准线的意义**：`check_fraud_pattern` 刻意做得"不够聪明"（只看字面特征）。
  它存在的意义之一就是**被高难负样本打脸**——家属真的要求保密、子女真的要钱，
  这些与诈骗话术表面同形。规则基线的失败正是"为什么需要证据抽取"的实验证据。

## 已知限制 / 未做

- 单机、合成轨迹评测；没有真实用户或线上部署。
  所有指标都是"在本仓库评测集上的离线结果"，**不代表能防住真实诈骗**。
- 语料依据公开反诈宣传材料中描述的手法合成，经 AI 逐条语义审阅；**尚无独立人类签核或双人一致性数据**，
  **不是真实案件数据**；不含真实受害人信息、不含任何公司内部数据、
  **不含可操作的作案细节**（只保留"对老人说什么"的诱导话术层）。
- 工具接口是真的，**数据是本地 mock**（SQLite 档案库）。不接真实账户、通讯录、短信通道；
  `notify_family` 只写库不真发。
- `docs/eval-report.md` 的"已知偏差与限制"一节列出了仍未解决的问题（包括单配置小样本 heldout、
  尚未完成的红队迭代、未测的老人模拟器，以及工具调用正确率为 0%）。
- 未做的项在报告里逐条标注，**不写成"已支持"**。

## 数据与合规

- **来源**：公开反诈宣传材料描述的手法作为分类参考；逐条种子出处未建立映射，不能声称每条样本均可溯源。经 AI 逐条审阅，未获独立人类签核。
- **边界**：只保留"对老人说什么"的诱导话术层；不含真实受害人数据或公司内部数据；自动合规审计与人工抽查结论见 [`docs/dataset-audit.md`](docs/dataset-audit.md)。
- **用途**：仅用于**防御性安全研究与合成轨迹评测**。禁止用于训练诈骗话术生成系统。
- 仓库带自动化合规预筛（`make dataset-audit`）：命中公司资产词、真实号码格式、
  作案细节词任一项即拒绝入库。

## 目录结构

```
silver-guard/
├── config/
│   ├── policy.yaml           # 策略表（等级→动作，热加载 + 版本化）
│   └── fraud_patterns.yaml   # 已知话术规则表（规则层的唯一来源）
├── src/silverguard/
│   ├── policy.py             # 策略引擎：确定性映射 + 热加载 + 失败降级 + 授权检查
│   ├── agent.py              # 四段式决策链路 / 四组消融配置
│   ├── tools.py              # 工具层：schema 校验 + 权限最小化 + 幂等 + 容错降级
│   ├── memory.py             # SQLite 记忆层：档案/白名单/事件/支出/会话状态/runs
│   ├── metrics.py            # 指标：确定性计算，附带公式注释
│   ├── runner.py             # 评测 runner（含阈值扫描、引擎开关、CI 门禁）
│   ├── redteam.py            # 自动红队共演进 + 老人模拟器（劝说成功率）
│   ├── replay.py             # 轨迹确定性回放
│   ├── service.py            # FastAPI + WebSocket
│   ├── mcp_server.py         # MCP server（stdio）
│   ├── gen_dataset.py        # 数据集生成 + 合规预筛 + 冻结划分
│   └── review.py             # 人工审核辅助：标注规则显式化 + 逐条对照
├── eval/dataset/             # attack.jsonl / benign.jsonl（进 git，带 sha256）
├── tests/                    # 离线单元测试

```
